\subsection{背景}
まず、私は介護ロボットに興味がある。
そこでLLMのような賢いロボットを作ることができないかと考えた。


私は、LLMはくそであると思う。
なまじ優秀な技術であるがゆえに、LLMを過大評価してしまう傾向がある。
もちろん、LLMは素晴らしい技術であることは間違いない。
\textbf{LLMはくそ}というのも、LLMについて疑問を抱いたことはないだろうか、私が特に着目したのは以下

\begin{enumerate}
    \item LLMなどtransfomerベースのモデルを、統計学的に扱うこと（幾何学や、制御論で論じれないか）
    \item LLMの出力の信頼性（特に、LLMが出力する数値の信頼性）
    \item 自発性（少し発展したものだが）
    \item 記号理解の問題
    \item データソースの倫理性
    \item attention機構の問題（特に、LLMの出力の安定性の問題）
\end{enumerate}

こういった理由から、既存のAIでは、ロボティクスに応用するのは難しいと考えている。
なぜならば、ロボティクスに応用するためには、LLMの出力の信頼性、安定性が必要であるからだ。

となると、統計的に扱うことの限界、それから応用的に思考をする自発性の問題が重要になってくる。
ここでは１つの解決の方法として構造的アプローチをとらせていただきたい。
もちろん、エンジニアリングからの解法だからといって、妄想的なものではなく、理論的に説明していきたい。

\section{ゲテモノ独自性}
まず、なんといってもpythonを限界まで使わないこと。mecabだけは使ったが。

またshaderで直で実装したことでコンパイルが通るものの、NNが局所解に陥った際に、次元を増やすことで解決することができる。幾何学的に見るととても簡単な話で、NN自体を成長させられるのも私の面白いところ。

\section{技術的説明}
wgpuという、CG用のライブラリからシェーダーというCGのための言語を使って、GPUでNNを実装している。
リダクションを図ることで、単体スレッドの１０倍程度の速度でNNの計算を行うことができる。（ものによっては１００倍など余裕で出るだろう）

次元拡張アルゴリズムについては、今のAIのあらかじめ決めたNN数の中で解くAIとのカウンターになっている。
次元拡張アルゴリズムは、$\delta$lossが小さいときに、次元を増やすというアルゴリズムである。
というのも、まず、NNの深さはNNの非線形関数の複雑性を表し、幅は次元数を表すと考えることができる。
例えば、ＸＯＲ問題に関しては深さ、幅ともに１で解くことができないが、深さを２にすることで解くことができる。これは２次元にプロットすると明快である。
問題は、ＮＮが局所解に陥ったとき、これはクラスの周りをクラスが囲うような形でプロットされているとクラス分けが不可能である。なので、次元を増やすしかない。
意外とこの手法をとるのはオーバーヘッドがあるということで好まれなかったが、shaderコンパイルレベルなので、サクサク動く。これによりトレースがかなり負いやすくなっている。

記号設置の確認方法として、感情行列を使ってdebugしているが、現実の生センサーとLLMの出力が競合していなければ、記号設置ができていると考えることができるのではないかと考えている。
